# My Notes — Build, Performance Audit & Verification Status

## 1. End-to-End Hot Path Audit (Before & After Changes)

We traced the complete handwriting & persistence pipeline (`PointerEvent` -> `InkSurface` -> `History` Command -> `Dexie.js` `IndexedDB` / `OPFS` commit):

| Pipeline Stage | Audit Findings (Before Changes) | Improvements Implemented |
|---|---|---|
| **1. Pointer Capture (`src/engine/surface.ts`, `src/engine/input.ts`)** | `onDown`, `onMove`, and `onUp` capture coalesced events (`getCoalescedEvents()` with fallback) directly into a typed `Float32Array` `SampleBuffer`. Zero React state updates occur during a stroke; rendering is driven by `requestAnimationFrame` on dual `<canvas>` layers (`scene` + `live`). | Preserved 100% engine-owned buffer capture, `penOnly` palm rejection, two-finger pan/zoom arbitration, and straightedge ruler snapping. |
| **2. Committed Scene Rendering (`src/engine/render.ts`)** | `drawScene()` called `strokePath(s)` (`getStroke()` from `perfect-freehand`) for **every visible stroke** whenever a stroke finished, a layer toggled, or the viewport panned/zoomed. On a dense page (350 strokes / 14,000 samples), recomputing 350 outlines took **`13.1 ms` (p50) / `26.4 ms` (p95)** on the main thread. | Added a bounded `Path2D` LRU cache (`MAX_PATH_CACHE = 2000`) in [`src/engine/render.ts`](file:///e:/My_Notes/src/engine/render.ts#L14-L90) keyed by `stroke.id + revision + width + tool + smoothing + samples.length`. Dense-page scene redraw time dropped from **`26.4 ms` (p95) down to `1.2 ms` (p95)** (`0.5 ms` p50) — a **22× speedup**. |
| **3. Command & Local Save (`src/domain/history.ts`, `src/app/store.ts`, `src/storage/db.ts`, `src/storage/blobStore.ts`)** | Unprotected strokes saved atomically via `repo.addStroke(s, nbId)` (`db.strokes` + `db.notebooks`). However, failed writes had no UI retry button, OPFS writes overwrote in place without `.staging` verification, and multi-tab edits did not notify sibling tabs. | Added `dirtyPages` tracking + `actions.retryFailedSaves()`, inline **Retry Save** and **Export Backup** buttons in the Editor header on write failure, `BroadcastChannel('mynotes-sync-v1')` cross-tab sync, and `.staging` write/verify/cleanup (`sweepOrphans`) in [`src/storage/blobStore.ts`](file:///e:/My_Notes/src/storage/blobStore.ts#L42-L95). |
| **4. Initial Bundle & Precache Contention (`vite.config.ts`, `src/app/Editor.tsx`, `src/app/Library.tsx`)** | `pdfjs-dist`, `pdf-lib`, and `fflate` were statically imported in the main entry (`2.10 MB` JS), and `ort-wasm-simd-threaded.jsep.wasm` (`21.60 MB`) was included in the automatic first-visit Service Worker precache (`24.75 MB` total precache). Furthermore, `registerType: 'autoUpdate'` could activate a new SW without user confirmation. | Lazy-loaded `pdfManager.ts` and `backup.ts` via dynamic `import()` (reducing main `index-*.js` from `2,104 KB` to `451 KB` / `139 KB` Gzip), excluded `ort-wasm` and `trocrWorker` from first-visit precache (reducing core offline precache from `24.75 MB` to `4.52 MB` raw / `2.11 MB` Gzip), and switched to `registerType: 'prompt'` with [`SafeUpdateBanner.tsx`](file:///e:/My_Notes/src/ui/SafeUpdateBanner.tsx) (**Later** / **Update safely** after flushing pending writes and snapshotting open tabs/page state). |
| **5. Network Independence (`@vercel/analytics`, `@vercel/speed-insights`, TrOCR, Gemini)** | Drawing, undo/redo, and IndexedDB/OPFS saves never call any network endpoint or Vercel Function. Analytics scripts load with `defer` and fail silently when offline; TrOCR runs in a dedicated Web Worker (`trocrWorker.ts`); opt-in Gemini uses `AbortSignal`. | Verified zero network dependency on the writing/saving path. Full size and capacity measurements documented in [`docs/APP_SIZE_REPORT.md`](file:///e:/My_Notes/docs/APP_SIZE_REPORT.md) and [`docs/CAPACITY.md`](file:///e:/My_Notes/docs/CAPACITY.md). |

## 2. Dense-Page Rendering Benchmark (Measured in Chromium `156.0.0.0`)

- **Hardware / Browser**: Windows 10 x64, 16 logical CPU cores, `devicePixelRatio: 1.25`, Chromium `156.0.0.0`, canvas `1200×900`.
- **Scene**: `350` committed ink strokes (`14,000` total `Float32` samples across `ballpoint`, `fountain`, and `brush` nibs).
- **Metric**: Main-thread `drawScene` execution time per frame (note: this measures JS + Canvas2D main-thread rasterization work, **not** hardware pen-to-photon display latency):
  - **Baseline (Uncached `getStroke` per frame)**: `p50 = 13.10 ms`, `p95 = 26.40 ms` (exceeded 16.6 ms 60 Hz budget and 8.3 ms 120 Hz budget).
  - **Improved (Bounded `Path2D` LRU Cache)**: `p50 = 0.50 ms`, `p95 = 1.20 ms` (**22× faster**, well within both 60 Hz `16.6 ms` and 120 Hz `8.3 ms` frame budgets).
